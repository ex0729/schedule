# USER FLOWS

- 최종 갱신: 2026-08-05
- 현재 구현 범위: 공통 인증과 최초 역할 선택

## 공통 흐름

1. 랜딩 → 회원가입 선택.
2. 강사/교육회사 담당자 역할, 이름, 이메일, 비밀번호 입력.
3. 서버가 입력 검증 후 Auth 계정을 생성하고 불변 제품 역할을 프로필에 기록.
4. 이메일 확인이 켜진 환경은 확인 메일 → callback → 보호된 대시보드. 꺼진 환경은 즉시 대시보드.
5. 이후 요청마다 서버가 세션을 검증. 비인증 사용자는 인증 화면으로 이동.
6. 로그아웃 시 서버가 세션을 폐기하고 랜딩으로 이동.

오류: 잘못된 필드에는 인라인 오류, 인증 실패에는 계정 존재 여부를 과도하게 노출하지 않는 공통 메시지를 표시한다. Supabase 미설정은 운영 오류가 아니라 개발 구성 오류로 명확히 알린다.

## 강사 핵심 흐름

가입/역할 → 강사 프로필 → 회사 초대/연결 → 기본 가능 시간 → 날짜 예외 → 개인/수업 일정 → 월·주 캘린더 → 회사별 공개 설정/미리보기 → 요청 확인/응답 → 배정 결과/자동 일정.

- 완료 조건: 본인 일정 원문을 관리하고, 연결 회사에는 정책에 맞는 계산 상태만 노출된다.
- 오류/예외: 시간 역전, 중복, 취소, 연결 해제, 요청 만료, 동시 배정 충돌을 복구 가능한 상태로 표시한다.

## 회사 핵심 흐름

가입/역할 → 회사 생성/가입 → 담당자 프로필 → 강사 초대/연결 → 수업 등록 → 조건 검색 → 후보 선택 → 요청 발송 → 응답 취합 → 최종 배정 → 운영 대시보드.

- 완료 조건: 필요한 인원만 배정되고 배정된 강사 일정에 확정 수업이 생성된다.
- 오류/예외: 다른 회사 리소스는 존재 여부도 노출하지 않고 404 또는 정책화된 403으로 처리한다. 인원 초과·중복 배정은 서버 트랜잭션에서 차단한다.

## 권한 분기

- 비인증: 랜딩/인증/콜백만 접근.
- 강사: 본인 프로필·일정·연결·요청·응답·배정 결과.
- 회사 담당자: 활성 멤버십 회사의 수업·연결 강사 계산 상태·요청·배정.
- 동시 역할 및 역할 전환 UX는 `[확인 필요]`; 현재 가입 시 단일 역할이다.
