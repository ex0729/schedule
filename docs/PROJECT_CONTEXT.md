# PROJECT CONTEXT

- 최종 갱신: 2026-08-05
- 기준 요구사항: `prd.md` v0.1
- 서비스: 디지털·AI 강사의 개인·수업 일정과 교육회사의 출강 인력 조사·배정을 연결하는 다중 조직 웹 서비스.

## 해결하려는 문제

- 강사는 흩어진 일정과 수업 정보를 반복 확인하고 입력한다.
- 교육회사는 전화·메신저로 여러 강사의 가능 여부를 묻고 수작업으로 취합한다.
- 회사에 필요한 것은 개인 일정 원문이 아니라 권한 정책을 통과한 출강 가능 상태다.

## 핵심 사용자와 흐름

- 강사: 가입 → 회사 연결 → 기본 가능 시간/예외/일정 등록 → 공개 정책 설정 → 요청 응답 → 배정 확인.
- 회사 담당자: 회사/강사 연결 → 수업 등록 → 가능 강사 검색 → 요청 → 응답 취합 → 최종 배정.
- 핵심 완료 흐름: 수업 등록 → 가능 강사 검색 → 출강 요청 → 응답 취합 → 최종 배정 → 강사 일정 자동 반영.

## 현재 MVP 범위

- PRD 12장의 15개 필수 기능 전체가 MVP다.
- 현재 구현: 인증·역할 선택 수직 단위. 다음 단계는 회사·강사 연결이다.
- 정산, 전자계약, 세금계산서, 학생/출결, 평가, AI 추천, 지도 이동시간, 카카오 자동발송, 외부 캘린더 동기화는 제외한다.

## 주요 제약

- 대한민국을 우선 지원하되 시간대는 `Asia/Seoul`로 하드코딩하지 않고 IANA 식별자로 저장한다.
- 개인정보 원문은 기본 비공개이며 회사 검색은 계산된 상태만 받는다.
- 회사 간 데이터 격리는 UI가 아니라 서버와 PostgreSQL RLS에서 강제한다.
- 이메일 확인, 발신 도메인, 백업, 모니터링은 운영 환경에서 별도 구성해야 한다.

## 미확정 사항

- `[확인 필요]` 한 사용자의 동시 역할 및 UI상의 역할/조직 전환 정책.
- `[확인 필요]` 한 강사와 여러 회사의 동시 연결에 대한 운영 정책. 모델은 허용한다.
- `[확인 필요]` 출강 요청 응답 변경 및 마감/재알림 정책.
- `[확인 필요]` 임시 일정이 가능 상태와 충돌 판정에 미치는 정책.
- `[법률 검토 필요]` 개인정보 보관기간, 국외 이전, 동의 문구, 처리위탁 고지.

## 절대 깨뜨리면 안 되는 원칙

- 개인 일정 제목·메모·장소는 기본적으로 회사에 공개하지 않는다.
- 가능 응답과 최종 배정은 서로 다른 상태다.
- 회사 A 사용자는 회사 B 데이터를 읽거나 변경할 수 없다.
- 모든 쓰기는 서버 인증·권한·입력 검증을 다시 거친다.
- 불확실한 정책을 코드의 암묵적 기본값으로 확정하지 않는다.
