# TEST STRATEGY

- 최종 갱신: 2026-08-05

## 계층과 게이트

- Unit: Zod 입력, 상태 전이, 시간 중복, 공개 정책, 배정 인원 계산.
- Integration: Supabase local/테스트 DB에서 RLS, trigger, transaction, server action.
- Component: 폼 키보드/오류/로딩/상태 배지.
- E2E: Playwright로 강사·회사 핵심 흐름과 모바일/데스크톱.
- 배포 게이트: lint → typecheck → unit → integration → build → 핵심 E2E.

## 필수 시나리오

### 인증·권한

- 비로그인 보호 경로 차단, 만료 세션 갱신/실패, 허용 역할만 가입.
- 강사 A가 강사 B 개인 일정 접근 불가.
- 회사 A 담당자가 회사 B 데이터 접근 불가(직접 ID/API 포함).
- 연결 해제/만료 즉시 접근 불가, 공개 수준별 응답 필드 차이.

### 일정

- 생성/수정/취소, 반복/예외, 타임존/DST 가능 지역, 월·주 조회 일치.
- 동일/포함/역포함/부분 중복, 경계가 맞닿는 비중복, 취소 제외.
- 임시 일정은 정책 확정 후 기대값을 고정한다.

### 요청·배정

- 복수 강사 서로 다른 응답, 대기/취소/변경 정책, 인원 미달/초과.
- 멱등 재시도, 이미 배정된 강사, 동시 배정 경쟁, 과다 배정 차단.
- 배정과 확정 일정 생성의 원자성, 배정 취소 후 일정 상태.

### 개인정보

- 모든 회사 응답에서 비공개 개인 제목·메모·장소가 키/로그/오류에도 없음.
- 회사별 정책/기간 차등, 가능 상태 계산만 노출.
- 감사 로그에 민감 원문/토큰 없음.

## 현재 자동 테스트

- `src/domain/auth.test.ts`: 정상 가입, 취약 비밀번호/알 수 없는 역할 거부, 이메일 trim, metadata 역할 파싱 제한.
- migration은 Supabase local 환경이 준비되면 `supabase db reset` 후 RLS 통합 테스트를 추가한다.

## 배포 전 수동 확인

- 키보드 전용, 스크린리더 이름/상태, 200% 확대, 색상 없이 상태 식별.
- 360px 모바일/768px 태블릿/1440px 데스크톱, 느린 네트워크, 빈/오류/권한 부족.
- 실제 이메일 확인/redirect allowlist, 로그 redaction, 백업 복구, rate limit.
